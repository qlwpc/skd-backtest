## 当前状态

已实现市场数据流、独立异步推理、运行缓存、共享数据包、组件入口和 Engine 接线。组件之间的账户、
分数、目标、费用、标签和结果均通过缓存交换；模型调用接口保持不变。
缓存只负责协议检查、数据持有及审计归集，不承担金融算法。

金融组件已实现并完成联合测试：Top-K / Barra 约束优化、真实交易限制、费用、
开盘与收盘估值、外部参考数据、未来收益标签、RankIC、15 项原始指标及 JSON/CSV 输出。
后复权模式以资产金额记账，真实价格模式以股数和真实价格记账；两种模式共享组件接口。
优化器只提供 Top-K 和 Barra 两种选择。Barra 使用已有暴露、参考权重和历史行业，统一执行
行业/风格/主动权重/换手约束下的排名分数优化；缺少必需输入或约束不可行时明确失败。
所有回测统一读取沪深300指数日收益并评价相对绩效，缺少指数数据明确失败；优化参考权重独立读取。现货账户不支持卖空，long_only=False 明确拒绝。
独立 `DataProvider.playback()` 同样可用，不需要调整基本示例的调用方式。

## 市场数据流

DataProvider.prepare 读取区间涉及的月度 MarketData 日期列，过滤、去重并排序，
形成每个实际交易日的日历。周末、节假日由真实数据决定。
按需向前读取日期列，寻找首日之前最多 `lookback - 1` 个交易日的预热历史；
到达数据集起点后使用已有历史，不补造数据。
Engine 一次 prepare 后由 playback 复用准备状态，独立 playback 则自动准备。

模型推理路径的三套完整数据默认每批读取 12 个自然月，使用一个标准库后台线程预取下一批。
冻结分数路径只读取执行行情和当日Barra，内部读取器不构造模型历史窗口；仍保留历史参考价扫描，
按原信号日经Runner发布已复制的分数，原组件及阶段协议继续负责所有金融处理。
播放缓存保留当前批次、所需历史尾部和最多一个待取批次，以及每只已出现股票的最近有效价格与日期。
模型历史窗口受 lookback 限制，参考价格状态不受该限制，不会缓存整个七年行情。
播放区间及模型预热期内，每个月的每套完整数据只读一次，日内接口使用已排序缓存切片。
日期列另有日历读取；必要时扫描更早 MarketData 的日期/代码/close/停牌状态，初始化历史参考价。
这次扫描独立于 lookback，按月处理、只保留每只股票的最近有效记录，文件缺失直接报错。
常规、跨批次及更早历史初始化均排除停牌或状态未知的报价，避免停牌报价在后一天进入估值。
`prefetch=False` 使用相同分批和切片逻辑，按需同步读取，供性能对照。
完整播放、提前关闭或异常时等待正在执行的读取结束，回收线程和缓存。

模型每次收到三张独立副本，日期范围是截至当日、含当日在内的最多 lookback 个交易日。
Factor33 和研究行情按每个历史日期的 Barra 成分过滤；
股票调入前不提供其非成分期历史，调出前的合法历史仍可出现在窗口中。
缓存可包含预取的未来日期，但传出的研究数据不包含未来行。
调用模型前先独立保存合法股票池：异步路径取当日市场包的 Barra 成分，同步路径取缓存中的相同成分。
Runner 在统一推理入口使用 Typeguard 装饰器，按 str、dict[str, DataFrame]、DataFrame 声明自动检查实际输入和模型结果；字典逐项检查。
用户无需继承类、添加装饰器或提供类型标注，构造时不执行推理；结果必须完整覆盖该池且分数有限；
模型修改其研究副本不能改变合法池或污染市场缓存。

DailyData 包含开盘行情、收盘行情、可选研究窗口与当日 Barra 输入；
只有研究窗口交给模型。市场数据仍直接传入相应组件，行情预取线程不访问运行缓存。
独立 `valuation_inputs()` 用自己的读数状态提供区间行情，不计算收益、不干扰播放。

后复权 open_market 必须调用 adjusted_limits.py 中的限价推算，不提供开关。
该模块独立按月读取 MarketDataRawOpen 的 open 与 Factor33_winsor 的 is_st，按日期/代码对齐并仅保留一个月缓存。
使用当天 adjusted_open/raw_open 比例将历史前收盘参考价还原到分，按板块、历史日期和 ST 标记计算原价上下限，
以 ROUND_HALF_UP 取至 0.01 元并保证至少一分钱的变动，再转回后复权口径。
不会读取当日 high/low/close 决定能否成交；研究、原价标签、真实价格模式和独立收盘估值不依赖此模块。
缺少所需数据不回退为不限制交易；历史参考价不足时 Broker 以 MISSING_PRICE_LIMIT 拒单。
涨停只限制买入、跌停只限制卖出，卖出失败后的买入仍受实际现金约束。
这条仅针对 1.0.x 的临时路径未重建新股上市等特殊交易安排，具体推算边界见使用说明。

真实价格模式支持月文件中的 raw OHLC 或 adjustment_factor（adjusted = raw × factor），
并要求提供当日 upper_limit/lower_limit；缺失必需字段或关键数据明确失败。
研究输入仍只保留原 SOURCE_COLUMNS，新增执行字段不进入模型。
Accounting 按持仓代码对齐行情，以 NumPy 数组批量计算价格、市值和权重，不再将逐股行情和持仓反复转换为字典。
停牌、缺价及历史参考价也通过 mask 选择，保持价格有效性、日期先后及同日优先级；收盘快照复用估值数组。
空持仓直接发布零市值快照；总市值保持原持仓顺序累计，输入快照不被修改。

Label Provider 不使用 DataProvider 实例：事后独立按需读取全市场日期和标签端点价格，
允许越过回测结束日取得持有期终点。停牌、缺价和数据集尾部不足均保留空标签及原因，不回填历史参考价。
Evaluator 使用平均并列排名计算 Spearman，Metrics 从审计表计算，不读取原始行情或改变账户。

## 推理流水线

Runner 支持加载标准 submission/inference.py 和多个 model/ 文件，也保留既有 callable 接口。
标准提交每次评测创建一个模型实例；同 Engine 重复 run 重新初始化模型。
random_seed 默认 0，模型加载和调用使用独立 Python/NumPy 传统随机状态，离开调用后恢复宿主状态。
直接传回调时，其内部模型状态由调用者管理；额外随机生成器及非确定算法须由提交固定，完整边界见使用说明。


`async_inference=True` 默认启用一个独立的模型线程，与 `prefetch` 的读取线程分别控制。
主线程仍是市场日历和账户的唯一推进者；它提前取得最多一个调仓间隔的逐日日包，按信号日期提交推理。
有界缓冲总上限为 `rebalance_interval + 1` 个日包（含待交付日），最多包含当前及下一信号的两个推理作业。
后台顺序调用同一个模型实例，不并发调用不同日期；每次仅收到截至对应日期的原有研究副本。
研究窗口提交后从日包释放引用，由任务持有，未新增深拷贝或跨进程序列化。

主线程可继续开盘、成交和收盘核算，到 SIGNAL 阶段才等待该日 Future，调用 Runner.publish_scores 发布分数，
然后执行 Optimizer。未来分数提前完成也不提前进入运行缓存；缓存和所有账户状态始终只在主线程访问。
关闭 `async_inference` 后恢复原顺序调用，可与读取预取独立组合。

模型或校验失败会阻止排队的后续模型调用，原异常在对应信号日交给主线程记录。
提前结束时取消尚未运行的任务，等待正在运行的模型返回，再回收推理、读取和缓存资源。
Python 线程不能强制中断用户回调；不自动重试、不静默切换执行方式。

## 运行缓存与执行顺序

每次 run 新建 RuntimeCache，按模式建立初始账户；组件仅持有各自角色的 CacheView。
主题具有固定生产者、读者、键、发布阶段和必需字段。表结构每次运行首次出现时检查一次；
阶段、权限、日期与计费身份等动态协议继续检查，逐行业务约束由唯一生产者保证。
发布和读取直接共享引用，发布后所有组件遵守只读约定；后续更新只复制真正改变的表，未变字段共享。
冻结数据包不会冻结 DataFrame 缓冲区及对象列，平台内部靠所有权契约保证快照不被修改。
审计按块保留表引用，跳过空目标/成交/持仓表，完整分数历史与最终结果各合并一次后复用。

Engine 按真实交易日推进：

1. INITIALIZE：打开运行日志，检查必需参考目录，准备日历，发布信号日与下一执行日。
2. SETTLEMENT：Broker 直接读取上一收盘账户（首日为初始账户），执行到期持仓解锁。
3. OPEN_VALUE：Accounting 使用开盘行情发布交易前账户估值。
4. EXECUTION：Broker 消费当天排期目标；逐笔计费请求由 Engine 交给 Cost Model，
   Broker 读取报价并继续，最后发布账户、订单和成交的完整数据包。
5. CLOSE_VALUE：发布当天基准收益，Accounting 使用收盘行情发布账户、实际权重及每日核算行。
6. SIGNAL：仅信号日且存在下一交易日时，桥接当日成分与 Barra，
   发布组合参考输入，等待该日推理并由 Runner 发布分数，Optimizer 发布下一开盘目标。
7. 每日结束释放临时状态；播放完成后依次执行标签、预测评价、指标和输出。

阶段推进要求必需产物齐全；目标只能在排期的下一交易日消费。
计费交换最多一个请求在途，报价消费后成对回收，缩量重新报价使用新请求 ID。
Broker 不持有 Cost Model，Engine 不解释费用或修改账户。

开盘快照与上日收盘快照分开保存，收盘实际权重由 Accounting 发布。
真实价格账户记录股数及锁定批次，后复权收益账户记录资产金额；
不能把后复权价作为真实成交价。
标签只在逐日播放结束后创建，读取权限仅给 Evaluator，不进入模型或优化器。
金融计算由业务组件实现，缓存仅检查结构和交接时点。

缓存保留运行配置、日历、当前/上一收盘账户和未来待执行目标，
审计历史按块保存，最终按需合并为七张结果表。历史审计和日志随运行长度增长，
不承诺整次回测恒定内存。

## 失败与输出

未发布、合法空表、`Dataset(status="unavailable", ...)` 分别表达尚无结果、
已完成且为空、数据源不可用，不可混用。数据根目录缺少必要来源或约束输入时明确失败。
Reference Data 从 data_dir 下的 HS300_index、HS300_weight、HS300_industry 懒读 CSV/Parquet，
指数来源固定为 HS300_index，目录缺失或数据无效时直接报错。
原始指数日线验证 SH000300 代码，将 YYYYMMDD 日期规范化，并将涨跌幅百分数转换为小数日收益。
首次加载验证固定结构、键和值；没有单独的来源路径或能力声明。
权重和行业支持原始 HS300_weight / HS300_industry 年度 GBK CSV 目录。
权重按日归一化，名单必须完整且恰好覆盖当日合法池；行业使用对应日期的行业代码，显示名称保留为附加字段。
原始文件不变；成分错位、缺少必需日期或字段、快照日晚于记录日直接报错。
源表和日期索引只保留本次运行，Engine 在成功和失败时调用 close，重复运行重新读取文件。

Writer 已实现本次运行独占的 run.log、配置记录、增量刷盘和关闭；
不修改全局日志设置。已有协议输出文件的目录被拒绝，避免覆盖或混合运行结果。
不配置 output_dir 时不写文件并发布 disabled 回执；配置后序列化 15 项指标及七张完整字段 CSV。
所有 CSV 先在临时目录写完，再移动至输出目录，metrics.json 最后成为完成标记。
输出发布或最终日志关闭失败时移除本次完成标记，保留日志和已写 CSV 用于排错。

主线程观察到组件异常后立即中断后续决策，记录原失败阶段、组件和原因，关闭计费生成器、
推理任务、市场读取资源、日志与缓存。提前计算的推理错误在对应信号日的 SIGNAL 阶段传播。清理失败也不会发布 engine.metrics/tables/account 成功状态。
重复 run 使用新缓存并重置 Writer 游标；同一输出目录已有日志时需另选目录。

成功运行的最终 API 已接好：返回 15 项指标，并接收最终账户和七张结果表的所有权，缓存关闭仅释放自身引用。
默认真实组件覆盖空区间和单日区间；指标 None 表示缺少有效样本或未定义比率。
Engine 使用 console.py 展示默认启用的交易日进度和结果表；展示仅读取已完成的计数与原始指标，
不参与缓存协议或金融计算。进度向标准错误输出并限频，成功表格只在资源清理成功后向标准输出打印。
`friendly_output=False` 时，引擎不主动打印进度或结果，评测入口向标准输出打印指标 JSON；命令行开关优先于配置文件。

## 文件归属与后续扩展

组件的完整签名、数据包及金融责任以 [接口协议](interfaces.md) 为准。
首版组件按以下范围独占文件开发并统一验收；后续扩展继续保持这一边界。
共享协议、配置、表结构和 Engine 的必要变更由基础设施维护者统一处理。

| 独占文件（均在 src/skd_backtest/） | 当前状态与剩余职责 |
|---|---|
| contracts.py、runtime_cache.py、config.py、schemas.py、engine.py、inference_pipeline.py、console.py、__init__.py | 公共类型、缓存、配置、接线及控制台展示已落地 |
| data_provider.py、adjusted_limits.py | 市场播放、历史参考价；后复权模式的强制限价推算与隔离读取，真实价格模式维持既有来源 |
| submission_runner.py | 标准提交加载、每次评测的模型及随机状态、推理校验；缓存发布仅在主线程执行 |
| reference_data.py | 精确日期的外部基准、权重和行业读取；合法池对齐 |
| label_provider.py | 独立按交易日读取端点价格，计算标签并保留缺失原因 |
| prediction_evaluator.py | 保留全部分数、按键对齐标签、平均并列排名的逐日 RankIC |
| portfolio_optimizer.py、risk_optimizer.py | Top-K、Barra 约束优化、排名信号与全部配置约束；统一输出 TargetPlan |
| broker.py | 日初结算、T+1、整手/零股、单边限价、现金缩量及计费交换 |
| cost_model.py | 日期生效费率、最低佣金、卖出印花税、过户费和方向滑点 |
| accounting.py | 开盘/收盘估值、逐日净值与收益及实际权重已实现并通过独立测试 |
| metrics.py | 15 项原始指标，明确样本标准差、年化、回撤和缺失语义 |
| result_writer.py | 运行日志、严格 JSON、七张 CSV 和失败完成标记清理 |

业务模块只依赖协议、缓存视图、自身配置和通用库，不互相导入业务类。
同一模块的多种算法仍归同一独占任务；新增私有辅助文件也必须指定归属。
集中业务测试在组件实现后统一整合，不要求各任务同时修改现有测试文件。

## 验证与打包

核心依赖 pandas、pyarrow、SciPy、typeguard 和标准库，不增加缓存服务或调度框架。
完整测试包含 benchmark 内存采样，需安装可选依赖：

```powershell
python -m pip install -e ".[benchmark]"
python -m unittest discover -s tests -v
uv build
```

也可安装 build 后执行 `python -m build`。

GitHub Release 标题只使用版本号；每次发布必须上传可由 pip 直接安装的 wheel，
并在发布说明中同时提供 pip 和 uv 安装命令。发布前在独立环境验证包版本、导入、命令行入口和基本回测，
发布后核对附件、标签提交及预发布状态。

当前版本为 `1.0.1`，项目元数据、wheel 和源码分发包均使用相同的 PEP 440 版本号。
GitHub Release 标题为 `1.0.1`，标签为 `v1.0.1`，发布时设为 Latest 以便仓库首页展示。
这是正式版本，GitHub 的 Pre-release 标记关闭。
发布包必须包含 Apache-2.0 许可证：wheel 的许可证目录和源码分发包的 LICENSE 均需核对。
构建内容须与发布标签提交一致，已有标签不移动。
本版更新与安装命令见[发布说明](releases/1.0.1.md)。

**Python API（个人单模型回测）**：用户对自己的单个模型进行回测时，建议参考 `examples/basic_usage.py` 使用 Python API。

**命令行评测（评测平台批量回测）**：`skd-backtest-evaluate` 是本包提供的命令行评测入口，推荐供评测平台批量调度；一次调用处理一个标准提交。
`-h`、`-help`、`--help` 展示这两种独立使用方式的说明和完整示例，回归测试检查说明分段以及帮助中的代码与独立示例一致。

测试覆盖临时月度数据的逐日播放、跨批次预热、成分过滤、同步/异步等价、
可见性、副本隔离、历史参考价、独立估值输入、提前关闭和线程异常清理。
